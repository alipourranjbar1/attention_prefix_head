# Train four-anchor DFlash with a known bonus embedding

Branch: `four-anchor-bonus20-train`. Base: `01d7dea27438c6c0578215f51b19a7d89c843cea`.

This trains the input layout used by `bonus_addon20_draft4_batch_v1`. It is a new
training objective, not an environment-variable change to the target19 recipe.

| Stage | Input | Query positions |
|---|---|---:|
| First draft pass | Four processed token IDs + their target features; known bonus ID using embedding only; 15 masks | 20 |
| Second draft pass | Four token IDs immediately before the restart + their corresponding first-pass drafter states; 15 masks | 19 |
| Native vLLM verification | Known pending bonus + 15 final candidate IDs | 16 |

For example, if processed history ends at token 10, pass one contains token IDs
7, 8, 9, 10 with target states, bonus ID 11 without a target state, and masks
for positions 12..26. If the restart is position 20, pass two uses IDs/states
at 16, 17, 18, 19; all four states come from the first drafter pass. If restart
is 12, the four states are at 8, 9, 10, 11 and STILL all come from the drafter.

Both passes use the original processed-prefix target context. Neither reads
the bonus's target features or target features for proposed tokens. No target
call occurs between draft passes. This is regular DFlash with five bidirectional
layers and one shared drafter, not a prefix-attention model or MTP.

## Training objective

- Four anchors, 15 speculative tokens. The bonus is a known input and has no
  prediction loss. Loss on round one is only the 15 masked positions.
- In packed training the known bonus ID is taken from the existing target-rollout
  sequence (teacher forcing). It is not generated by an extra target call per
  sampled block. Teacher states at the bonus and later positions are used only
  to supply next-token loss targets, never as drafter inputs.
- Round two reuses detached first-pass drafter states for all four anchor
  queries, even for anchors at original prefix positions. Their token IDs are
  reused as well. The first pass now retains all 20 output states for this.
- Boundary scoring uses the existing D-Loop confidence score plus the existing
  training exploration schedule. Training caps the retained prefix at the first
  dataset-token mismatch so cached teacher labels describe the same prefix.
  Inference uses confidence without this teacher-forcing cap. The INPUT layout
  is matched; training is not an exact on-policy rollout simulation.
- Round-two loss covers only the replaced part of the original 15-position
  candidate window. Both passes run even when the boundary is zero.
- Default loss is `0.1 * CE + 0.9 * TV`, in both passes. CE uses the teacher's
  greedy token and TV uses the full teacher distribution. KL is not part of
  this default loss. The existing chunked vocabulary projection is preserved.
- New checkpoints record `anchor_layout=bonus_addon`, `format_version=4` and
  `num_proposals=15`. Older target19 checkpoints cannot be resumed as this
  objective; start a fresh run. Resume is supported within format 4.

## Install on the other server

Activate your existing working Ascend Conda environment. From the root of your
clone of `four-anchor-15-train-benchmarks`, after copying the ZIP to this server:

```bash
(
  set -euo pipefail
  source_repo="$PWD"
  package_dir="$(mktemp -d)"
  unzip -q /path/to/four-anchor-bonus20-train.zip -d "$package_dir"
  python "$package_dir/four-anchor-bonus20-train/install.py" \
    --source-root "$source_repo" \
    --destination "$(dirname "$source_repo")/four-anchor-bonus20-train"
)
```

The installer creates a new sibling worktree and branch. It checks the package
files, preserves the original clone's tracked files/index/branch and writes
no checkpoints. It records the original clone as the default dependency root.
It does not install packages, initialize/update submodules, or start/stop jobs.
Dependencies must already be initialized: Speculators, vLLM at
`77b1d88c5b52abaf6a103292119f3435b51699d9`, vLLM-Ascend at
`276a5c840b21c83b153d3ebd831720bc926dfc4e`.
If your working dependency checkout is elsewhere, set `VLLM_SOURCE_ROOT` and
optionally `SPECULATORS_ROOT` to that checkout before running.

## Run training

Set these paths for THIS server; the launcher does not assume paths from the
old machine:

```bash
cd /path/to/four-anchor-bonus20-train
export MODEL=/path/to/local/Qwen3-4B
export DATASET=/path/to/open_perfectblend.qwen3-4b-rollout.qwen3.seq3072
export CANN_ROOT=/path/to/CANN/9.1.0
bash four_anchor/scripts/train_bonus20_ascend.sh
```

`DATASET` must be the preprocessed Hugging Face `save_to_disk` directory with
`input_ids` and `loss_mask`. If CANN/ATB is already fully sourced, `CANN_ROOT`
may be omitted. No automatic dependency installation is performed.

Defaults:

| Setting | Value |
|---|---|
| Teacher NPUs | 0,1 |
| Training NPUs | 2,3,4,5,6 |
| Checkpoint benchmark NPU | 7 |
| Distributed strategy | FSDP |
| Packed token budget | 9216 **per training rank** |
| Maximum sampled blocks | 1536 **per packed batch per rank** |
| Draft layers | 5 bidirectional |
| Epochs / learning rate | 5 / 0.0006 |
| Training split ratio | 1.0; no held-out training-data evaluation |
| Benchmark concurrency | 32 |
| Benchmark samples | up to 128 from each available cached benchmark |
| Maximum generated tokens | 2048 |
| Baseline evaluation | Off |
| Target/drafter graphs during evaluation | Off |

Settings can be overridden with environment variables. `MAX_ANCHORS` is the
number of sampled training blocks; the conditioning anchor count stays FOUR.
The progress bar uses actual packed batch counts. No training-time guarantee
is made: two-pass work, hardware and data packing determine runtime.

Before loading the teacher, the launcher runs the existing small distributed
FSDP preflight, now with this new objective. `CHECK_ONLY=1` validates imports,
configuration and the packing plan without launching NPU jobs. `MAX_STEPS=2`
can run a short hardware smoke test in a fresh output directory. A partial
first epoch produces a checkpoint but is not queued as a completed epoch.

## Automatic benchmark evaluation and saved results

Evaluation remains asynchronous after each COMPLETED epoch, on physical NPU 7.
Training proceeds on NPUs 2..6. The worker uses the included batched bonus20
inference with the same input layout, four drafter-state anchors in round two,
concurrency 32 and no AR baseline. It uses native vLLM target verification with
zero additional bonus-only target forwards.

The suite discovers local cached GSM8K, MATH-500, HumanEval, MBPP, LiveCodeBench,
AIME25, MT-Bench and Alpaca data. It freezes prompts once. Smaller datasets use
all available examples up to the limit. Unavailable datasets are reported as
skipped; preparation errors are recorded rather than silently replaced with
other data. `BENCHMARK_CACHE_DIR=/local/cache` adds a cache location.
`BENCHMARK_PLAN=/local/prepared/plan.json` reuses an existing local frozen plan;
absolute paths inside plans copied from another server must be valid there.
If no benchmark can be prepared, the launcher stops before training starts.
`EVAL_EACH_EPOCH=0` explicitly disables the evaluator if wanted.

The run directory is printed at launch and defaults to:

```text
output/bonus20_train_<timestamp>_<pid>/
```

Files inside it:

| Path | Meaning |
|---|---|
| `checkpoints/checkpoint-<step>/` | Draft weights, format-4 metadata, optimizer and RNG states |
| `checkpoints/logs/four_anchor_dflash/` | TensorBoard |
| `train.log` | Progress, losses, throughput and ETA |
| `evaluation/epoch_results.md` | Combined results table across epochs |
| `evaluation/epoch_results.csv` | Same results for analysis |
| `evaluation/epoch_results.json` | Checkpoint identities, statuses and result paths |
| `evaluation/epoch-002/<attempt>/summary.md` | Second completed epoch benchmark table |
| `evaluation/epoch-002/<attempt>/<benchmark>/two_pass/summary.json` | Individual benchmark metrics |
| `evaluation/worker.log` | Worker progress/errors |

Acceptance includes one correction/bonus and excludes the four conditioning
anchors: maximum 16 per verification cycle before EOS/output-budget truncation.
Throughput is aggregate output tokens divided by measured generation wall time
at concurrency 32. Task accuracy and exact output parity are not measured by
the default suite. No speedup is claimed without a matching baseline.

## Validation and limitations

See the packaged `VALIDATION.json` and test logs. Local CPU tests compare both
training passes against the batched inference for all 15 restart boundaries,
check bonus/future/document isolation, gradients, zero-boundary redrafting,
checkpoint export, epoch queue routing, and installation isolation. Ascend
training and vLLM execution of NEW format-4 weights must be checked on the
server; this package does not claim a measured acceptance or speed gain.

To resume, set `RESUME=/path/to/this-run/checkpoints/checkpoint-...` and launch
again with the same dataset, rank count and training recipe. The run directory
is inferred from the checkpoint when `OUTPUT_DIR` is unset.
